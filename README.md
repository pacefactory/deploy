# Pacefactory deployment bootstrap

Public bootstrap for [deployment-scripts](https://github.com/pacefactory/deployment-scripts),
the tooling that builds and runs a Pacefactory SCV2 deployment. Served by
GitHub Pages at `https://get.pacefactory.dev/install.sh`.

## Install or repair deployment-scripts on a server

```bash
curl -fsSL https://get.pacefactory.dev/install.sh | bash
```

Run it as the account that operates the deployment (normally `pacefactory`),
not as root. It is idempotent: use the same command for a first install, to
convert a server that still holds the old `git clone`, or to repair a broken
install. It pulls the private release image `pacefactory/deployment-scripts`
from Docker Hub, extracts it and hands off to the updater shipped in the image
(`scripts/release/fetch-release.sh`), which syncs the tree into the install
directory by manifest. Site files (`.env`, `.settings`, `docker-compose.yml`,
`credentials/`, custom compose fragments, `scripts/remote/servers.txt`) are
never touched. It does **not** run `build.sh` or `update.sh`; it prints them
as the next steps.

## Prerequisites

- Linux host with Docker Engine and the docker compose plugin
  (`docker compose version`).
- The user running the one-liner is in the `docker` group: `docker info` works
  without `sudo`. The script never uses `sudo`.
- Docker Hub access as the organization user `pacefactory`, one of:
  - a per-server Docker Organization Access Token stored as
    `export DOCKER_OAT=dckr_oat_...` in `~/scv2/docker_oat.sh` (mode 700). How
    tokens are issued is described in the Pacefactory Deployment Guide, not
    here. The script logs in with it and never prints or copies it;
  - or an existing `docker login` as `pacefactory` on the server.
- Egress to Docker Hub (`registry-1.docker.io`, `auth.docker.io` and the
  Docker Hub CDN) over HTTPS 443, directly or via the site proxy (`source
  ~/connect-to-proxy.sh` first where the site uses one), plus
  `get.pacefactory.dev` for this script only.
- For `build.sh` afterwards: mikefarah `yq` v4 on PATH
  ([Install yq](https://github.com/pacefactory/deployment-scripts/blob/main/docs/how-to/install-yq.md)).

## Environment variables

The script never prompts and takes no positional arguments.

| Variable | Default | Purpose |
|---|---|---|
| `PF_INSTALL_DIR` | `$HOME/scv2/git_clones/deployment-scripts` | Install root. Keep the default so the fleet tooling and docs keep working. |
| `PF_IMAGE` | `pacefactory/deployment-scripts` | Release image repository. |
| `PF_RELEASE` | `latest` | Tag to install. `PF_RELEASE=v1.2.3` pins a release or rolls back to it; `sha-<short>` tags exist for every build. |
| `PF_REMOVE_GIT` | `false` | `true` deletes a converted checkout's `.git` directory after a successful sync. |
| `PF_OAT_FILE` | `$HOME/scv2/docker_oat.sh` | Token file sourced for `docker login`. |
| `DOCKER_OAT` | unset | Honoured if already exported. Never pass a token as an argument. |

Examples:

```bash
# pin a release
PF_RELEASE=v1.4.0 bash -c "$(curl -fsSL https://get.pacefactory.dev/install.sh)"
# or, keeping the pipe form
curl -fsSL https://get.pacefactory.dev/install.sh | PF_RELEASE=v1.4.0 bash
```

## Sites that forbid pipe-to-shell

Download, verify against the checksum committed in this repository, then run:

```bash
curl -fsSLo install.sh https://get.pacefactory.dev/install.sh
curl -fsSLo install.sh.sha256 https://get.pacefactory.dev/install.sh.sha256
sha256sum -c install.sh.sha256
bash install.sh
```

`install.sh --dry-run` prints the resolved configuration without touching
Docker. `install.sh.sha256` is regenerated by hand on every change
(`sha256sum install.sh > install.sh.sha256`); CI fails when it is stale.

## After the install

Follow the deployment-scripts how-tos:
[Install or repair deployment-scripts on a server](https://github.com/pacefactory/deployment-scripts/blob/main/docs/how-to/install-deployment-scripts.md)
(what the conversion changes, rollback), then
[Build a deployment](https://github.com/pacefactory/deployment-scripts/blob/main/docs/how-to/build-a-deployment.md)
and [Update a deployment](https://github.com/pacefactory/deployment-scripts/blob/main/docs/how-to/update-a-deployment.md).
Routine updates on an installed server use `./scripts/release/fetch-release.sh`
inside the install directory; this bootstrap is only for install and repair.
